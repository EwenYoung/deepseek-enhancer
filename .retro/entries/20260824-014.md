DOM 重依赖代码的端到端自验：jiti 跑 TS 源码 + CORS receiver 收真实页面 DOM + 真实管线生成预览再断言。

- **症状**：「历史会话导出」这类 bug 藏在 DOM 抓取逻辑里，纯单测覆盖不到，等用户人工验证才发现已太晚
- **原因**：真实页面的 DOM 结构（装饰元素、组件嵌套）无法在 node 测试里复现
- **解法**：① node_modules/.bin/jiti script.mjs import src/**/*.ts（jiti 已在依赖里）跑真实导出管线；② node http server（Access-Control-Allow-Origin: *）收 POST 落盘，页面 evaluate_script 里 fetch('http://localhost:PORT/', {method:'POST', body: JSON.stringify(数据)}) 传出 DOM 数据（text/plain 免预检）；③ 真实源码处理真实数据生成预览 → 本地 http 服务 → 浏览器程序化断言
- **适用条件**：DOM 重依赖层的提交前验证
